# DATABASE SCHEMA & OPTIMIZATION

## Overview
PostgreSQL relational schema designed for high-performance loan matching and batch lifecycle tracking.

## Tables

### 1. `users`
- Stores user financial and demographic profiles imported from CSV.
- Key Columns: `user_id` (UUID PK), `monthly_income`, `credit_score`, `employment_status`, `age`, `batch_id`.
- `batch_id` scopes operations so Workflow B only processes the newly uploaded batch rather than full-table scans.

### 2. `loan_products`
- Stores product criteria crawled from banks (Workflow A).
- Key Columns: `product_id` (SERIAL PK), `product_name` (UNIQUE for upserts), `interest_rate`, `min_income`, `min_credit_score`, `employment_types` (TEXT[] array), `min_age`, `max_age`.
- `employment_types` is stored as a PostgreSQL array to allow multi-status qualification (e.g. `{'Salaried', 'Self-Employed'}`).

### 3. `matches`
- Records qualified user-to-product pairs generated by Workflow B.
- Key Columns: `match_id` (SERIAL PK), `user_id` (FK), `product_id` (FK), `match_score` (0.00-1.00), `match_reason`, `batch_id`, `notified` (BOOLEAN).
- `notified` flag prevents duplicate email alerts when Workflow C executes.

## Indexes & Performance Optimization
- `idx_users_filter (batch_id, monthly_income, credit_score, age)`:
  Enables index scans during Stage 1 SQL pre-filtering in Workflow B, reducing matching complexity before rule evaluation or LLM calls.
- `idx_matches_batch (batch_id, notified)`:
  Allows Workflow C to fetch unnotified records in constant time.
